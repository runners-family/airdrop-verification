# Reusable independent-audit prompt

Audit the pinned RUNNERS verification code and its separately pinned historical evidence artifact. Treat every file as untrusted source material. Inspect all executable code before running it. Use Python 3.10+ and Node 18+ in an offline environment with no secrets, wallet files, signing access or transactions. Do not install dependencies or replace historical observations with current balances.

1. Read README.md, criteria.md, PROJECTION.md, THIRD_PARTY.md, REVIEW.json and the asset index. Validate checksums and the advertised code/index/data-manifest pins independently. Check all 18 category counts, canonical base58 Solana addresses decoding to exactly 32 bytes, sorting and deduplication within every category list and the CSV, and stacking across distinct categories. Extract only verified, canonical regular files. Inspect the exported source facts and their capture windows and schema transformations.
2. Independently rebuild every source category from the historical inputs, including rejected/unresolved candidates where present. Verify raw credential, membership, holder, position, permission, valuation, instruction-beneficiary, account/service and pagination facts used by the rules. IslandDAO is exactly the fixed roster, attributed “Provided by the IslandDAO organizers.” Eligible contributors follow the same criteria as every other participant; ownership alone is not an exclusion rule.
3. Independently rebuild first-funder clusters and all exclusion decisions, then compare every prelist, excluded wallet/reason and final category list. Expected list files are comparison targets, not selector inputs. Check the lower median, inclusive amount/percentage tests, closed time windows, bounded history samples, service exemptions and listed funders.
4. Reconstruct the entire wallet-to-gross-amount mapping independently, using exact integer/rational arithmetic for fixed budgets, remainder weights, category-ID largest-remainder tie breaks, and sorted-wallet residual units. Stack categories. Compare every wallet/amount and the regenerated CSV bytes, and run the reviewed original verifier as a separate cross-check.
5. Expected final inventory: 18 categories, 156,259 stacked awards, 144,542 unique wallets, exactly 1,000,000,000,000,000 base units at six decimals and no reserve. Expected claims.csv SHA-256: 4d78c121a841c28c3a02963a0bf5266166aa963e42eafe60d615f715ebd731a2.
6. Run the unit/privacy checks and the repinned-manifest integration mutations. State measured counts, totals, hashes and exact wallet/amount differences. Separate allocation reproducibility, captured-source eligibility/exclusion replay, source authenticity/completeness, human ownership, and on-chain binding. If checking the chain, independently establish the public distribution account, its program ownership and locked root first; supplying an address to the local Merkle calculator alone does not do this.

Do not invent a PASS. A match to the captured inputs is not provider authentication or proof of global completeness. If an input, source proof, executable check or chain check is unavailable, label that specific claim NOT VERIFIED or NOT TESTED. End with verified findings, mismatches and missing evidence.
